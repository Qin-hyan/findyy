# C. Findy 技术架构决策（阶段一收口 · 2026-10-28）

> 本文是阶段一调研（[A：检测与实例关联](A_detection_reid.md)、[B：检索/存储/查询](B_retrieval_storage_query.md)）与阶段二实现之间的决策记录。
> 结论分为「已实现并验证」「已实现未验证」「未实现」三类，避免把推断写成事实。

---

## 0. 结论摘要

1. **端侧只采集，全部推理放笔记本**。ESP32-S3-EYE 继续沿用已验证的 M1 固件（拍照 / Wi-Fi / SNTP / HTTP），不在端侧跑检测。依据：Espressif 官方 `esp-who` 只提供人脸、行人、二维码等专用轻量示例，没有通用检测；端侧算力与内存也不适合（详见 A §1.6）。
2. **检测采用开放词表 OWLv2，而不是闭集 YOLO**。COCO 80 类不含钥匙、钱包、眼镜、耳机、充电器、U 盘等 Findy 核心物品（A §1.2）；同时 Ultralytics 系列为 AGPL-3.0，闭源分发有传染风险（A §1.4）。OWLv2 走 HuggingFace 实现（Apache-2.0 系），规避该风险。
3. **同一实物关联采用「DINOv2 外观 embedding + 颜色直方图 + 区域先验 + 时间衰减 + 固定机位 bbox IoU 加分」的加权打分，输出三态判定**（matched / ambiguous / new）。不存在可直接使用的桌面物品实例 re-ID 预训练模型（A §2.1），因此必须自建并如实暴露不确定。
4. **存储使用 SQLite 单文件 + 文件系统图片**，时间语义严格区分 `captured_at`（设备 SNTP 时间，可为 NULL）与 `received_at`（本机接收时间），**未同步时绝不伪造墙钟时间**。
5. **自然语言查询以规则解析为主干**（中文别名表 + 意图模板），不依赖任何云端 LLM；查询结果必须带证据图、时间、区域、置信度与依据说明。
6. **位置用「命名区域」而不是 3D 坐标**：固定机位下用归一化多边形把画面划分成区域（如「桌面左侧/中央/右侧」「抽屉」），检测框中心点归属区域；这是低成本、可解释、可验证的位置表示，不谎称三维定位。

## 1. 约束与目标

| 约束 | 取值 | 对架构的影响 |
|---|---|---|
| 已有硬件 | ESP32-S3-EYE v2.2 + OV2640，M1 固件已验证 | 直接复用 HTTP 接口，不重写采集 |
| 计算 | 普通 Windows 笔记本（本机 i7-14650HX / 15.7GB RAM，CPU 推理） | 单帧秒级推理可接受，低频抓拍（10–60s/帧） |
| 成本 | 不购买付费服务、不新增硬件 | 全本地、开源模型；无订阅/云存储 |
| 目标物品 | 桌面杂物，大量超出 COCO 80 类 | 必须开放词表或用户注册 |
| 位置精度 | 无深度/无标定相机 | 用画面区域 + 归一化坐标，诚实说明粒度 |
| 时间 | 设备 SNTP，可能失败 | 时间来源显式建模，未同步=明确标记 |

## 2. 候选路线与取舍

### 2.1 视觉推理放在哪里

| 方案 | 优点 | 缺点 | 决策 |
|---|---|---|---|
| ESP32-S3 端侧推理 | 无需传图、隐私最好 | 官方无通用检测示例；模型/内存受限（A §1.6） | ❌ 不采用 |
| 本机 CPU 推理（OWLv2 + DINOv2） | 复用现有电脑、离线、可解释 | 单帧 6–11s（本机实测） | ✅ **采用** |
| 云端视觉 API | 精度高、无需下载模型 | 有费用、图像外传、断网不可用 | ❌ 不采用（与低成本/隐私约束冲突） |

### 2.2 检测器

| 方案 | 覆盖 Findy 物品 | 许可 | 决策 |
|---|---|---|---|
| YOLO11/YOLOv8（COCO） | ❌ 无钥匙/钱包/眼镜等 | AGPL-3.0，闭源分发有传染风险 | ❌ 不作为交付栈 |
| **OWLv2（开放词表）** | ✅ 词表可配置，覆盖桌面杂物 | Apache-2.0 系（HF 实现/权重卡） | ✅ **采用** |
| Grounding DINO | ✅ 开放词表 | Apache-2.0（A 标注待核） | 备选（接口已抽象，可替换） |
| 用户注册样例 + 单样本检索 | ✅ 精确到「这一件」 | 自研 | ⏳ 后续增强 |

实现为可插拔 `Detector` 接口，`config/findy.yaml` 的 `detector.backend` 可切换 `owlv2` / `mock`。

### 2.3 实例关联

| 方案 | 适用性 | 决策 |
|---|---|---|
| 行人 re-ID 预训练模型 | 场景/评测口径不同源，不能外推精度（A §2.1） | ❌ |
| ByteTrack/BoT-SORT | 依赖连续帧运动模型；60s 间隔失效 | ❌ 跨天关联不用 |
| **DINOv2 embedding + 颜色 + 区域 + 时间先验** | 与固定机位、低频抓拍匹配 | ✅ **采用** |
| SIFT 几何二次校验 | 遮挡/同款多件时有用 | ⏳ 未实现（接口预留） |
| 用户注册照（gallery） | 把「同款多件」降级为单样本检索 | ⏳ 未实现（界面可人工确认合并） |

### 2.4 检索与存储

| 方案 | 决策 |
|---|---|
| SQLite 元数据 + 文件系统图片/裁剪图 | ✅ 采用（规模 <10 万条足够，零运维） |
| 向量库（FAISS/hnswlib/sqlite-vec） | ❌ MVP 不需要，numpy 暴力比较足够；预留 `embedding BLOB` |
| 纯文件 JSON | ❌ 查询/索引/事务能力不足 |
| 云数据库 | ❌ 与本地化约束冲突 |

### 2.5 自然语言查询

| 方案 | 决策 |
|---|---|
| 规则解析（别名表 + 意图模板 + 颜色/区域/时间槽位） | ✅ 主干、默认、离线 |
| 云端 LLM function calling | ⏳ 可选增强，默认关闭（无密钥、无费用） |
| 本地小模型 | ⏳ 后续（当前 CPU 预算优先给视觉） |

结果必须展示：匹配物品、证据图、观测时间、区域、置信度、关联依据、以及「不确定/时间未同步」等限制说明。

## 3. 选定架构

```
┌────────────────────────────┐        HTTP (LAN)
│ ESP32-S3-EYE (M1 固件)      │  POST /api/capture
│ 拍照 + Wi-Fi + SNTP + HTTP  │  GET  /api/photo?seq=N
└────────────┬───────────────┘
             │ JPEG + 真实时间/未同步标记
             ▼
┌──────────────────────────────────────────────────────────────┐
│ 笔记本 · Python 3.11+（本仓库 findy/）                        │
│                                                              │
│  sources.py ──► pipeline.py ──► detector.py (OWLv2 开放词表)  │
│  (esp32/replay/upload)   │      embedder.py (DINOv2 + 颜色)   │
│                          │      matcher.py  (三态关联判定)    │
│                          ▼                                   │
│                     db.py (SQLite) + data/images, data/crops  │
│                          │                                   │
│  query.py（中文规则解析 + QueryPlan 执行器）◄─────────────────┤
│  api.py (FastAPI) + web/（单页界面）                          │
│  service.py（定时自动采集线程）                               │
└──────────────────────────────────────────────────────────────┘
```

### 3.1 模块职责（全部已实现）

| 文件 | 职责 |
|---|---|
| `findy/sources.py` | ESP32 M1 HTTP 适配、图片回放、上传；强校验 seq/JPEG/时间来源 |
| `findy/pipeline.py` | 抓拍入库 → 检测 → 裁剪/颜色 → embedding → 关联 → 落库 |
| `findy/detector.py` | OWLv2 开放词表检测（逐类阈值、逐类 NMS）、Mock 后端 |
| `findy/embedder.py` | DINOv2 ViT-S/14 CLS 向量（L2 归一化）、测试用平均哈希替身 |
| `findy/matcher.py` | 余弦/颜色/区域/时间打分、双阈值三态决策（纯函数，可单测） |
| `findy/zones.py` | 归一化多边形区域、点归属、未标定时的方位兜底 |
| `findy/db.py` + `findy/schema.sql` | SQLite 访问层、幂等抓拍、物品轨迹、候选关联、反馈、查询日志 |
| `findy/query.py` | 中文意图/槽位解析 + 8 类执行器 + 带证据的中文回答 |
| `findy/api.py` | HTTP API、上传、图像服务、自动采集控制、设备探测/会话级切换、验收接口、静态页面 |
| `findy/service.py` | 自动采集循环（失败可见、不静默） |
| `findy/acceptance.py` | 验收运行/事件证据、六项 PASS/FAIL/NOT VERIFIED 判定、脱敏导出 |
| `web/workbench.*` | `/workbench` 端到端验收工作台（运行状态、设备、检测、轨迹、查询、验收总览、引导） |
| `findy/__main__.py` | `serve/status/capture/query/replay/esp32` 命令 |

### 3.2 数据模型（SQLite，见 `schema.sql`）

`cameras` / `regions` / `captures` / `object_classes` / `aliases` / `tracks` / `detections` / `link_candidates` / `feedback` / `query_log` / `acceptance_runs` / `acceptance_events`。

关键设计：

- `captures(camera_id, device_seq)` 唯一：设备重试不会重复入库（幂等）。
- `captures.captured_at_utc` 允许 NULL，配合 `time_synced`、`time_source`；`received_at_utc` 独立记录。
- `tracks` 保存原型向量（float32 BLOB）与颜色直方图；`detections` 保存每次观测的 bbox/区域/置信度/关联分。
- `detections.captured_at_utc`、`region_id` 冗余存储，查询「某物 + 时间 + 区域」走复合索引。
- `link_candidates` 保存灰区候选，供界面人工确认；`feedback` 记录确认/纠错，为后续阈值校准积累数据。
- `captures.source_kind` 记录每帧真实来源（esp32/replay/upload）；`detect_ms/embed_ms/process_ms/detect_error` 记录真实耗时与失败原因。老库按既有 `time_source` 语义回填来源，不覆盖明确值。
- `acceptance_runs`/`acceptance_events` 保存本轮验收模式、操作事件与证据；六项结论由事件+数据库真实记录计算，replay 演示强制 `simulated=true`，真机结论只接受 `source_kind=esp32` 的抓拍。

### 3.3 关联策略（已实现）

```
score = 0.70·cos(DINOv2 原型, 当前)
      + 0.15·颜色直方图相似度
      + 0.10·区域先验（同区 1.0 / 异区 0.35 / 未知 0.6）
      + 0.05·时间新鲜度 exp(-Δt/24h)
score = min(1, base + 0.15·IoU(当前框, 该轨迹最近框))   # 固定机位空间先验
status = matched   (score ≥ 0.82)
       | ambiguous (0.70 ≤ score < 0.82) → 新建轨迹 + 记录候选，界面提示待确认
       | new       (score < 0.70)
```

- 原型向量按 `alpha=0.2` 指数滑动更新，避免单帧噪声带偏。
- 同帧内同一轨迹只允许绑定一个检测（一对一），避免重复归属。
- 类别不同的检测不互相匹配。

### 3.4 时间语义（已实现，验收覆盖）

- 设备 SNTP 已同步：`time_synced=true`，记录 `captured_at_utc/local/epoch_s`。
- 未同步：`captured_at_utc=NULL`，`time_source='sntp_unsynced'`，界面与回答明确显示「时间未同步」。
- 回放图片：文件名时间戳 / sidecar / 文件 mtime 三种来源，均写入 `time_source`，不冒充设备时间。
- 上传：只有客户端显式给了 UTC 时间才标记为已同步。

### 3.5 位置语义（已实现）

- `config/zones.yaml` 定义归一化多边形区域（默认桌面左/中/右）。
- 检测框中心点落入区域 → 记录 `region_id/region_name`；未标定 → 用「画面左上/中央…」方位兜底，并标记 kind=`frame_grid`。
- 这是**画面区域**，不是三维坐标；文档与界面均不得表述为「精确位置」。

## 5. 已实现并验证 / 未验证

### 已验证（有本项目证据）

- 6 帧演示序列端到端：检测→入库→跨帧关联→中文查询→界面展示（见 `docs/evidence/`）。
- **真实 ESP32 硬件**：6/6 抓拍、38 次检测、8 条轨迹，5 类主物品 6/6 帧关联同一轨迹；UI 真机点击抓拍 7/7 检查通过（见 `docs/evidence/hardware/`）。
- 71 个自动化测试通过（关联、解析、存储、API、ESP32 适配器 mock、异常路径）；2026-10-29 工作台增补后为 **89 项通过**。
- 浏览器真实交互 12 项检查通过（Chrome + Playwright，截图存证）；2026-10-29 工作台 replay 演示 **38/38** 通过（含真实 OWLv2 检测、跨帧关联、查询、六项状态、脱敏导出）。
- 时间未同步场景：接口/界面/回答均明确标注，不伪造时间。
- 设备 seq 幂等与旧图拒绝：单测覆盖。
- 无效 JPEG 上传返回 400；不存在的抓拍/裁剪图返回 404；采集源不可用返回 503 且带错误原因。

### 未验证（不得声称通过）

- 长时间/多天真机运行、断线重连、镜头移动后的重标定未验证；M1 固件自身的实机 100/100 拍摄证据在其独立仓库 `D:\Findy-Firmware\docs\M1_RESULTS.md`。
- **真实桌面/真实物品**：演示数据来自公开 COCO 图片 + 变换模拟不同时刻；真实场景的检测召回率、关联准确率**未测**。
- **工作台真机流程**：2026-10-29 工作台验收时设备未连接，设备连接/真实抓拍/真机检测/存储/轨迹/查询六项均 **NOT VERIFIED**；需设备在线后现场复验，不得用 replay 冒充。
- 长期运行稳定性、Wi-Fi 断线重连、NTP 漂移、>1000 帧容量与清理策略。
- 同款多件（两支一样的笔）区分能力：无 ground truth，未测。
- 多用户/鉴权：当前仅监听 `127.0.0.1`，无鉴权；若改为局域网监听必须补访问控制。

## 6. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 开放词表误检/漏检 | 记录噪声、查询不准 | 逐类阈值（`objects.yaml`）、界面显示置信度、候选待确认、反馈表积累数据 |
| 小物品分辨率不足 | 钥匙/耳机等漏检 | 建议设备改 UXGA（A §1.7 建议）；词表默认阈值已按小目标放宽并注明需现场校准 |
| 同款多件误合并 | 记忆错乱 | 双阈值三态 + 候选确认；后续用户注册照 |
| CPU 推理慢（单帧 6–11s） | 自动采集间隔受限 | 低频抓拍（默认 60s）；可换更小输入/ONNX/GPU |
| AGPL 许可风险 | 闭源分发 | 交付栈不使用 Ultralytics；依赖许可清单见验收报告 |
| 隐私 | 摄像头画面 | 仅默认监听本机；不启用 webcam 采集；图像与查询不出本机；`data/` 不入库 |
| 时间不可信 | 历史顺序错乱 | 双时间字段 + 未同步显式标记；查询按入库顺序兜底 |

## 7. 下一阶段可选优化（按性价比排序）

1. 用真实桌面/ESP32 设备做 1–2 天小样本标定实验（A §4 的 Acc@1/FAR/UR 协议），重新校准阈值。
2. 用户注册照 + 同款多件消歧（产品价值最高）。
3. 变化检测触发采集 + 保留策略（容量与隐私）。
4. SIFT/ORB 几何校验，降低同款多件误合并。
5. 中文 CLIP 第二路语义召回 + 向量索引（规模上来后）。
6. 区域可视标定页、抓拍失败重试与断线重连、鉴权与局域网访问控制。
